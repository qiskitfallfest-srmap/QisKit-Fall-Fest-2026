## 1. AI Agent Operating Protocol & Governance (MANDATORY)

Every AI agent working in this codebase must strictly abide by the following operational directives:

1. **The Caution Principle (Never Assume — Always Ask):**
   - This repository houses the public face and digital summit platform of Qiskit Fall Fest 2026.
   - If an event time, speaker name, venue, registration rule, or date is unconfirmed, **never invent details or add placeholder copy**.
   - Cross-check against the companion Planning Repository (`01 _ TECHNICAL & INNOVATION TRACK QFF`) and prompt organizers when in doubt.
2. **Anti-Slop Standards & Engineering Restraint:**
   - **Zero Decorative Emojis:** Never place raw Unicode emojis in code, UI elements, buttons, cards, headers, status badges, toast notifications, error banners, logs, or commit messages (e.g., no emojis like `⚡`, `✨`, `🚀`, `💡`, `✅`, etc.). Use clean SVG icons (such as Lucide) or clean text labels.
   - **Clean Light-Theme Preference:** Default to a crisp, modern light theme (`#ffffff` / `#f8fafc`, subtle borders `#e2e8f0`, legible dark typography `#0f172a`, restrained accents) unless dark theme is explicitly requested. Avoid gratuitous glowing animations or neon halos.
   - **Concise, Functional UI Copy:** Action-oriented, direct labels (`Turn On`, `Refresh`, `Connected`, `Register Free`). Zero corporate AI filler words (*"delve"*, *"tapestry"*, *"landscape"*, *"seamless"*, *"game-changer"*).
   - **Hardware Safety:** Passive monitoring only. Never initiate unsolicited hardware actuation or pulsing.
3. **Route & Architecture Guardrails:**
   - **First-Party Registration Rule:** The "Join Free" and "Register" CTAs route directly to `/learning` with instant on-site self-registration.
   - **Component Scoping:** Shared primitives belong in `components/shared/` or `components/ui/`; page-specific compositions belong in `components/pages/[route]/` or `components/[feature]/`.
   - **Data Stores:** All schedules, venue mappings, and event metadata are centralized in `data/`. Do not hardcode static event data inside UI render loops.
4. **Continuous Learning & Logging:**
   - Every AI agent session that implements features, resolves bugs, or updates data **must log its actions** in [Section 6: Chronological Agent Activity Log](#6-chronological-agent-activity-log) before concluding.

1. **Root Cause Analysis (`getActiveSheet` on `null`)**:
   - When Google Apps Script is bound to a Google Form or when a trigger is created from event source "From form", the execution container is `FormApp.getActiveForm()`. In this container, `SpreadsheetApp.getActiveSpreadsheet()` strictly returns `null`, and the trigger event object passes `e.response` (`FormResponse`) rather than `e.range`.
   - Invoking `SpreadsheetApp.getActiveSpreadsheet().getActiveSheet()` within `onFormSubmit(e)` under a form trigger throws `TypeError: Cannot read properties of null (reading 'getActiveSheet')`, preventing the webhook POST to the website and stopping email dispatch.
2. **Dual-Container Resolution Architecture (`tools/google_form_webhook.gs`)**:
   - **Spreadsheet Trigger (`e.range` present)**: Resolved directly via `e.range.getSheet()` and `e.range.getRow()`.
   - **Form Trigger (`e.response` present)**: Extracts participant responses directly from `FormResponse.getItemResponses()` and `getRespondentEmail()`. Dispatches HTTP POST to the portal webhook and sends the confirmation email immediately, eliminating any failure dependency on spreadsheet access.
   - **Resilient Spreadsheet Finder (`getTargetSpreadsheet()`)**: Cascades through (1) `SpreadsheetApp.getActiveSpreadsheet()`, (2) explicit fallback `SPREADSHEET_ID_OR_URL`, and (3) `FormApp.getActiveForm().getDestinationId()`.
3. **One-Click Batch Recovery**:
   - Both `syncAllUnsyncedRows()` (for Google Sheets) and `syncAllFormResponses()` (for Google Forms) iterate through historical records, synchronizing unsynced attendees to Supabase/Redis and dispatching missing welcome emails with polite rate-limiting (`Utilities.sleep(300)`).

### GT-38: Rolling Phase 2 Results, Waiting Room Auto-Promotion & Lead-Pays-Last Flagship Payment
1. **Per-team release instead of one publish switch**: Jury decisions are released team by team from `/learning/admin` > Phase 2 Results (`components/learning/AdminPhase2View.tsx`, `app/api/admin/phase2/route.ts`). `submission_evaluations.result_released_at` gates visibility; `participant_feedback` is the note shown to the team (the `comments` JSON stays internal). The legacy `hackathon_phase1_results.published` flag still releases everything at once, so keep it `false`.
2. **Offers table**: `hackathon_phase2_offers` (migration `20261018150000_create_phase2_waiting_room.sql`), one row per team (`UNIQUE team_id`). States: `invited -> accepted -> confirmed`, or `declined | expired | revoked`. Only the team lead accepts/declines (`app/api/hackathon/phase2/route.ts`).
3. **Auto-promotion**: Any close of an `invited`/`accepted` offer invites the highest-scoring waitlisted team (`status in under_review, needs_discussion`) in the same track that never had an offer (`lib/phase2-waiting-room.ts`). Concurrency safety comes from conditional `UPDATE ... WHERE status IN (...)` (only the closer promotes) plus the unique `team_id` (two promoters cannot invite the same team). Track = lead email `@srmap.edu.in` or SRM AP institution in `participant_universities`.
4. **Deadlines are lazy**: overdue offers expire on any admin GET, on the affected team's `/api/pass/status`, and every few minutes via `/api/cron/phase2-sweep` (Bearer `PHASE2_SWEEP_SECRET`, called by Supabase pg_cron + pg_net).
5. **Payment order**: accepted members pay ₹499 individually; `/api/pass/claim` refuses the lead's claim until every other accepted member has a non-rejected `flagship_offline` claim. The lead's claim marks the offer `confirmed`. Payment deadline is per team (`pay_by`); `flagship_payment.gateway_url` only supplies the Easebuzz link.
6. **Participant copy**: `components/learning/Phase2StatusCard.tsx` covers every stage (not released, waitlist position, invited, paying, confirmed, declined, expired, revoked, not selected / waiting room closed) with calm wording and a contact line. Waitlisted and invited teams cannot buy the General Pass until their outcome is final.
7. **Accept = commitment; payment clock waits for the link** (18 Oct 2026): The Easebuzz link comes from ITKM after invitations go out. The lead must tick a commitment (whole team attends, everyone pays within the window) before `accept` (enforced server-side with `committed: true`). Accepting with no link sets `pay_by = NULL`, which never expires; `startPendingPaymentWindows()` (run by every sweep) sets `pay_by = max(link opened_at, accepted_at) + payment_window_hours` once `flagship_payment` has `gateway_url` and `opened_at`. Defaults: 24 h to accept, 24 h to pay.
